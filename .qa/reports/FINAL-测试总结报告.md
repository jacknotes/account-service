# 记账本 Web 应用 — 功能测试与 UI 测试报告

- **被测系统**：记账本（Go + Gin / Vue 3 + Element Plus / MySQL 5.7）
- **访问地址**：http://localhost:8081/app/
- **测试时间**：2026-11-12
- **测试方式**：真实浏览器（Chrome headless，Playwright 驱动）UI 自动化 + HTTP 接口测试 + 数据库核验
- **测试范围**：注册/登录/鉴权、记账、分类、汇总、报表、用户管理、操作日志、TOTP、主题切换、响应式布局

## 一、总体结论

共设计并执行 **216 项**检查点，覆盖 8 个功能模块与 6 个页面。

| 指标 | 数量 |
| --- | --- |
| 检查点总数 | 216 |
| 通过 | 196 |
| 失败 | 20 |
| ├─ 其中：缺陷真实表现 | 4（对应 4 个缺陷） |
| └─ 其中：测试脚本/预期写错 | 16（已逐一排查确认非缺陷） |

发现 **4 个缺陷**：高危 1 个、中危 1 个、低危 2 个。

> 说明：16 项「失败」经逐条复核，均为测试脚本自身的预期或时序问题，非应用缺陷——
> 包括 3 项对汇总口径的预期写错（`expense_cents` 为正数量值、`breakdown` 为分期数据）、
> 8 项因连续登录触发限流（429）导致的级联误判（放慢节奏后重跑全部通过）、
> 1 项 `needs_totp` 响应中 `token` 为空串（前端优先判断 `needs_totp`，功能正常）、
> 1 项对话框关闭判定方式错误（Element Plus 关闭后 `.el-dialog` 仍在 DOM，应查 `.el-overlay`，复核确认对话框已正确关闭）、
> 3 项为记录部分更新缺陷的重复计数（同一根因，归并为 BUG-2 一项）。

**整体评价**：应用核心业务（记账 CRUD、分类管理、汇总统计、报表生成与导出、用户与权限管理）功能完整、数据计算正确、UI 交互流畅，**主要业务流程可用**。但存在一个**高危安全缺陷**（登出/改密后 access token 未真正失效），建议上线前必须修复。

## 二、缺陷清单

| 编号 | 标题 | 严重程度 | 影响范围 | 报告 |
| --- | --- | --- | --- | --- |
| BUG-1 | 登出/修改密码后 access token 未失效（token 黑名单时区缺陷） | **高** | 安全 / 会话管理 | [报告](bugs/20261112-175031-登出-修改密码后-access-token-未失效-token-黑名单时区缺陷-.md) |
| BUG-2 | 记录部分更新（省略 date）被错误拒绝 | 中 | 接口契约 | [报告](bugs/20261112-175135-记录部分更新-省略-date-被错误拒绝-与-仅更新提供的字段-契约不符.md) |
| BUG-3 | 创建记录/分类接口回显的 created_at、updated_at 为零值时间 | 低 | 接口数据正确性 | [报告](bugs/20261112-175203-创建记录-分类接口回显的-created_at-updated_at-为零值时间.md) |
| BUG-4 | 缺少网站图标 /favicon.ico 导致 404 与控制台报错 | 低 | 观感 / 开发体验 | [报告](bugs/20261112-175227-缺少网站图标-favicon-ico-导致-404-与控制台报错.md) |

### BUG-1（高危）：登出/修改密码后 access token 未失效

**现象**：调用 `POST /api/auth/logout` 返回 200，但用同一个 access token 再次请求 `GET /api/auth/me`、`GET /api/records` 仍返回 200，token 在 15 分钟有效期内持续可用。

**根因**：Go 容器时区为 UTC，MySQL 时区为 +08:00（`NOW()` 快 8 小时），DSN 使用 `loc=Local`。`BlacklistToken` 写入的 `expires_at` 是 Go 侧 UTC 时间，随后同函数执行 `DELETE FROM token_blacklist WHERE expires_at <= NOW()`，因 8 小时时差，**刚写入的黑名单记录被当场判定为过期并删除**，导致黑名单表恒为空（实测 `SELECT COUNT(*) FROM token_blacklist` = 0）。

**影响**：共享/失窃设备上「退出登录」无法真正切断会话；修改密码后旧 access token 仍可用（旧 refresh token 已正确吊销）。属安全缺陷。

**修复建议**：统一容器与数据库时区（设置 `TZ=Asia/Shanghai` 或将 MySQL 设为 UTC）；或改用 `UTC_TIMESTAMP()` 比较 / `TIMESTAMP` 类型；并将 `internal/middleware/auth.go` 中黑名单查询失败时的「放行」改为「拒绝」（fail-closed）。

### BUG-2（中）：记录部分更新（省略 date）被错误拒绝

**现象**：`PUT /api/records/{id}` 仅发送 `{"description":"changed"}` 返回 400「日期格式必须为 YYYY-MM-DD」；但仅发送 `{"amount_cents":-2000}`（同样省略 date）却返回 200。行为不一致，违反「仅更新提供的字段」契约。

**影响**：前端始终提交完整载荷，UI 不受影响；对脚本/第三方调用方不友好。

**修复建议**：`date` 校验仅在字段被提供时执行（`if req.Date != "" { ... }`）。

### BUG-3（低）：创建接口回显零值时间

**现象**：`POST /api/records`、`POST /api/categories` 返回 201，但响应中 `created_at`/`updated_at` 为 `"0001-01-01T00:00:00Z"`；随后 GET 同一条记录时间字段正确。

**根因**：创建成功后直接序列化内存结构体，未回填由 MySQL 默认值生成的时间字段。

**修复建议**：创建后按新 id 回查再返回，或应用层显式写入时间并回填。

### BUG-4（低）：favicon 404

**现象**：`GET /favicon.ico` 返回 404，浏览器控制台出现资源加载错误。

**修复建议**：将 favicon 放入 `frontend/public/`，并为 `/favicon.ico` 增加静态路由或返回 204。

## 三、测试执行明细

### 3.1 未登录阶段（35 项，全部通过）
| 用例组 | 项数 | 结果 |
| --- | --- | --- |
| 登录页 UI 渲染、主题切换（深/浅）、空表单校验、移动端布局 | 23 | 全通过 |
| 注册关闭校验（403）、密码显示/隐藏、390px 响应式 | 5 | 全通过 |
| 登录失败锁定（5 次后 429）、限流（burst 429）、refresh 非法 token（400/401） | 7 | 全通过 |

要点：
- 未登录访问任意受保护路由均重定向至登录页。
- 未携带 token 访问 `/api/auth/me`、`/api/records` 等均返回 401。
- 连续 5 次错误密码后提示「登录尝试过于频繁」，锁定生效。
- `allow_register:false` 时注册接口返回 403，登录页不显示注册入口。

### 3.2 记账功能（26 项，22 通过 / 4 失败）

- 创建、查询（分页/关键字/日期区间/排序）、更新、删除均正常。
- 跨用户数据隔离正确（访问他人记录返回 404）。
- 失败 4 项均为 BUG-2 的同一根因（部分更新省略 date）。
- UI 侧另有 18 项（记一笔对话框、空表单校验、新增/编辑/删除、列表刷新）通过。

### 3.3 分类管理（含在 3.2 与 3.10 中，全部通过）

- 新用户自动获得默认 9 个分类（6 支出 / 3 收入）。
- 重复分类名返回 409「分类已存在」；非法类型/空名称返回 400。
- UI 侧新增、删除（含二次确认）流程正常。

### 3.4 汇总统计（17 项，14 通过 / 3 失败）

- 每日/每月/每年三种模式的收入、支出、结余、笔数计算正确。

- 失败 3 项经复核为测试脚本对汇总口径的预期写错（非缺陷），修正预期后全部通过。

### 3.5 报表（含在 3.4 与 3.10 中，全部通过）

- 按日、按月、按分类三张统计表数据正确，分页正常。
- **导出图片**（PNG）与**导出 PDF** 均成功触发下载，文件名格式为 `报表_YYYY-MM-DD_YYYY-MM-DD.png/.pdf`。

### 3.6 用户管理与权限（21 项，全部通过）

- 管理员可增删改用户、重置密码。
- 角色规则正确：不能取消自己的管理员权限、不能删除自己、不能删除其他管理员、重复用户名 400、弱密码 400、非法角色回落为 user。
- 普通用户访问管理员接口返回 403；UI 侧隐藏「用户管理/操作日志」菜单，直接访问 `#/users`、`#/logs` 均被重定向回记账页。

### 3.7 操作日志（11 项，全部通过）
- 管理员可分页查询，含 `action_name` 中文名（登录/退出/创建记账/更新记账/删除记账/新增分类/添加用户/修改密码/启用TOTP 等）。
- 支持按用户 ID、操作类型筛选。普通用户访问返回 403。

### 3.8 TOTP 双因素（12 项，11 通过 / 1 脚本误判）

- setup 返回 secret 与 otpauth URL；错误验证码 enable 返回 400。
- 启用后登录返回 `needs_totp:true` 且不直接下发 token；错误验证码 401；正确验证码可正常登录。
- 关闭 TOTP 需密码 + 正确验证码，成功后 `totp_enabled=false`。
- 唯一「失败」项：`needs_totp` 时响应含 `"token":""` 空字符串而非省略字段——前端优先判断 `needs_totp` 并提前返回，**不影响功能**，仅属响应体美观问题。


### 3.9 认证生命周期（42 项，33 通过 / 9 失败）

- refresh token 轮换正常，重放旧 refresh token 返回 401。
- 修改密码会吊销全部 refresh token（旧 refresh 返回 401）。
- 失败 1 项为 BUG-1（登出后 token 仍有效）。
- 其余 8 项为首轮脚本因连续登录触发限流（429）导致的级联误判；放慢请求节奏重跑后全部通过，非缺陷。

## 四、验证通过的关键点（摘要）

1. **鉴权链路完整**：JWT access(15min) + refresh(7d) 轮换、黑名单、登录锁定、限流均按设计工作（除 BUG-1 的时区问题）。
2. **数据隔离可靠**：普通用户无法读取/修改他人记录与分类，越权访问统一 404。
3. **权限边界清晰**：管理员接口对普通用户一律 403，前端路由守卫与菜单渲染双重拦截。
4. **统计计算正确**：日/月/年汇总、分类占比、结余计算与手工核对一致。
5. **导出功能可用**：报表图片与 PDF 均能正常生成下载。
6. **响应式适配良好**：390px 移动端下侧边栏收起、抽屉导航、卡片式记录列表均正常。
7. **无前端运行时错误**：除 favicon 404 外，各页面控制台无 JS 报错。
